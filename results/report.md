# 사이클 평가 보고서: 제안 기법 vs D-Box

작성일 2026-11-05. 대상 보드 STM32L562E-DK. 기준 커밋 9679590 (측정 코드는 `BENCH_*` 매크로로만 추가).

표기: [실측] 이번 측정, [논문] D-Box 논문, [코드] 소스/디스어셈블, [도출] 측정값 간 계산, [추정] 근거가 부족한 해석.

## 1. 결론

1. **DMA 검증 비용은 제안 기법이 D-Box보다 훨씬 작게 측정된다.** `verify_inst` 순수 비용은 18~62 사이클(보정 후)이고 D-Box 검증은 평균 657 사이클이다. 중재자 전체도 D-Box와 같은 32MHz에서 182 사이클이다. 다만 코어, 측정 경계, 검증 내용이 달라 배수로 비교할 수 없다.
2. **context switch는 D-Box보다 크게 증가한다.** D-Box는 +5 사이클(1.74%)이고, 제안 기법을 쓰는 태스크는 secure context 때문에 +184~+544 사이클(54~77%)이다. 이것이 D-Box 대비 가장 불리한 항목이다. 원인은 MPU 영역 추가가 아니라 TrustZone의 secure context 저장·복원이다.
3. **macro 오버헤드 %는 제안 기법이 훨씬 크게 나오지만 직접 비교할 수 없다.** 1~100B 평균이 Insecure DMA 대비 254.9%(캐시 off)다. D-Box는 평균 4.71%다. 이쪽 baseline은 M2M이라 매우 짧고 D-Box는 주변장치 전송이다. 공통으로 말할 수 있는 것은 "전송당 거의 고정된 비용이 추가된다"는 점이고, 이쪽 고정 비용은 518~720 사이클(캐시 off), 224~385 사이클(warm)이다.
4. **828은 중재자 비용이 아니다.** 약 458 사이클이 전송 완료 ISR과 NS 콜백이다. 나머지 대부분은 ICACHE off와 Secure -O0의 영향이다. ICACHE on + Secure -O1이면 중재자가 112 사이클이다.

**미완료:** P0(전부 -O0) 측정과 디버거 비연결 CYCCNT 검증은 수행하지 못했다 (§8).

## 3. 측정 인프라 검증 (Phase 1)

**측정 경계** [코드]
- `statMediator`/T0→T5: `SECURE_dma_m2m_start` 호출 직전~복귀 직후. SVC, mutex, 큐 연산은 없다. mutex는 구간 밖이다.
- CYCCNT 판독 주체: 벤치마크 태스크가 특권이어서 NS에서 직접 읽는다. syscall을 거치지 않는다.

**CYCCNT 신뢰성** [실측, `results/phase1/summary.md`]
- 연결 상태: `DWT_CTRL=0x40000001`(CYCDISS=0), `DAUTHSTATUS=0xFF`.
- NOP 4096 최솟값: NS 7196, Secure 7204, NS에서 본 Secure 호출 7447. **Secure 구간도 세고 있다.**
- 비연결 상태: **미측정** (§8).

**보정값 (연속 판독 차, 최솟값)** [실측]
| 조건 | NS | Secure (-O0) | Secure (-O1) |
|---|---|---|---|
| off | 3 | 20 | 7 |
| warm | 3 | 8 | 3 |
| cold | 3~9 | 16 | 3 |

아래 표는 NS 경계 값은 원값이다. "보정 후"라고 쓴 곳만 보정값을 뺐다.

**계측 왜곡** [실측]: 타임스탬프를 넣으면 T0→T5 중앙값이 P1_off 827→1002, P1_warm 467→507로 늘어난다. 그래서 절대값은 무계측 변형을 쓰고, 타임스탬프 변형은 구간 비율과 순서를 볼 때만 쓴다.

- P1_warm IRQ 차단값 204에서 TTAT 몫 7을 빼면 약 197이다 [도출]. 논문 160과 약 37 차이가 남고 원인은 미확인이다.
- 828과 160의 차이 대부분은 ISR 중첩(458), ICACHE off(165)로 설명된다 [도출].

max는 틱 인터럽트 선점이 포함된 값이다. N=10에서는 틱에 걸릴 확률이 낮아 max가 작다: P1_off `verify_inst`의 max가 N=10에서 82, N=1000에서 518이다. D-Box의 10샘플 min/max와 비교할 때 이 차이를 고려해야 한다.

### 5.2 Context switch

| 조건 | 미할당 | 할당 | 증가 |
|---|---|---|---|
| **D-Box** [논문 Table IV] | **287** (F-MPU) | **292** | **+5 (1.74%)** |
| P1 off 32MHz | 379 | 650 | +271 (71.5%) |
| P1 off 110MHz | 723 | 1267 | +544 (75.2%) |
| P1 warm 110MHz | 363 | 607 | +244 (67.2%) |
| P2 warm 110MHz | 363 | 559 | +196 (54.0%) |
| P2 warm 32MHz | 329 | 513 | +184 (55.9%) |

증가의 의미가 다르다. D-Box는 MPU 영역 1개 추가의 비용이고, 이쪽은 `SecureContext_SaveContext`/`LoadContext` NSC 호출 비용이다 [코드]. 제안 기법은 NS-MPU 영역을 더 쓰지 않으며 커널 전환 코드를 고치지 않았다. 따라서 Secure를 호출하지 않는 태스크 사이의 전환은 미할당 값이 적용된다. DMA 태스크는 NSC를 호출하므로 secure context가 필요하다.

경계도 다르다: 이쪽은 `t0` 판독→yield→PendSV→MPU 재설정→다음 태스크 판독까지이고, D-Box는 "context switch routine"이라고만 쓰여 있다.

|---|---|

| 생성 256워드, P1 off 32MHz | 18630 |
| 생성 128워드, P1 off 32MHz | 14022 |

- 생성 비용은 스택 크기에 크게 좌우된다(128워드 차이로 4608 사이클). D-Box 스택 크기는 미확인이므로 절대값을 비교할 수 없다.
- 제안 기법은 `xTaskCreateRestricted`에 검증을 추가하지 않았다 [코드]. D-Box의 증가분에 대응하는 항목은 태스크 첫 실행 시의 secure context 할당이다. 태스크 수에 따른 변화는 측정하지 않았다.

**% 비교가 불가능한 이유:** 오버헤드 %는 baseline에 반비례한다. 이쪽 baseline은 메모리 복사라 짧다(25B Insecure 318 사이클). D-Box baseline은 주변장치 전송 시간을 포함하는데 논문에 절대값이 없다. 그래서 D-Box 추가 사이클을 역산할 수 없고, 이쪽 값과 나란히 놓을 수 없다.

공통점: 양쪽 모두 오버헤드가 길이에 반비례한다. D-Box 논문도 전송당 고정 비용이라고 설명한다(§VII-B2). 이쪽 길이당 비용은 Insecure와 제안이 사실상 같다.

## 7. D-Box와의 차이 원인

P1_off 8B 기준. 기여량은 [실측]의 차이다.

| 원인 후보 | 판정 | 근거·기여량 |
|---|---|---|
| 전송·ISR 중첩 | 측정 경계 문제로 확인 | 중재자 827 중 458. D-Box 검증값에는 해당 없음 [추정] |
| 측정 경계 차이 | 큼, 정량화 불가 | `verify_inst`/중재자/왕복이 62/369/854로 경계에 따라 14배 차이. D-Box 경계는 논문에 없음 |
| 검증 내용 차이 | 큼 | 이쪽은 TT 명령 4개, 통과 경로 15개 명령 [코드]. D-Box는 영역과 capability 정책을 소프트웨어로 대조 [논문]. 정확한 코드 비교는 미수행 |
| 보안 상태 전환 | D-Box에 없는 비용 | 빈 NSC 169(off), 60(warm), 77(32MHz). D-Box는 SVC와 태스크 전환 비용이 있으나 validation 수치 포함 여부 미확인 |
| 플래시 대기·캐시 | 큼 | IRQ 차단값 369(off)→204(warm), 4096 NOP 7196→2147 |
| 클럭 차이 | 큼, 주로 플래시 대기를 통해 작용 | 110→32MHz: IRQ 차단값 369→182(off), 204→168(warm). 캐시 warm이면 빈 NSC와 verify는 동일(60, 29) |
| 최적화 | 중간 | IRQ 차단값 369→275(off), 204→112(warm). P0 미측정 |
| Secure context | context switch 차이의 주원인 | +184~+544 |
| 코어 차이(M3/M33) | **미측정** | 이 보드로 실험 불가 |
| 표본 수 | max에 영향 | `verify_inst` max 82(N=10) vs 518(N=1000). min/중앙값은 거의 동일 |
| 전송 종류 | macro %의 주원인 | M2M vs 주변장치 (§6) |

가장 공정한 비교 조건은 **32MHz + 캐시 off**다. D-Box와 클럭이 같고 L152RE에 명령 캐시가 없다고 보았다 [추정, 미확인]. 다만 코어와 경계는 여전히 다르다.

N=10과 N=1000 사이에 빌드가 달라 코드 배치가 바뀌면 최솟값이 약 7 사이클 움직인다 (P1_off IRQ 차단 376 vs 369, 빈 NSC 162 vs 169). 이 정도 차이는 의미 있는 변화로 해석하면 안 된다.
